🕐 Timestamp display (History & User Logs)
ℹ️ Every timestamp this portal writes already includes the correct +05:30 (IST) offset. If SharePoint/Power Automate strips that offset before handing the value back (a very common connector quirk), the digits you get back are already IST — not UTC. Converting them again to IST would then shift the displayed time ~5:30 hours too far ahead, which is the most common cause of "wrong IST hours" in History / User Logs.

Hover any Date & Time cell in the History or User Logs tables to see the raw value the database returned, right next to the computed time. Compare it with the live 🕐 clock in the top-right: if the table's time is consistently ~5:30 hours ahead of what actually happened, switch this to "Already IST" (recommended default). If it looks ~5:30 hours behind instead, switch it to "UTC — convert to IST".

❌ "Item Not Found" (Flow 6, Loop Delete)

Cause: Get old items and Delete item point to different lists.
Fix: set both to INTEGERATED GMT Checklist; Delete Id = items('Loop_Delete')?['ID'].

❌ "…may not be null or empty: 'file'" (Read NewSheet)

Cause: PayloadFile is empty in the History row.
Fix: Flow 1 → PayloadFile = outputs('Create_file')?['body/Id'] (NOT {Identifier}). Re-upload, approve the new row.

❌ HTTP 401 (any flow)

Cause: the flow URL has no SAS signature.
Fix: re-copy the trigger URL; it must end with &sp=…&sv=1.0&sig=…. Build the flow in the same environment as your working signed flow.

❌ HTTP 502 (Flow 5 Get Pending)

Cause: Filter Query / Select error on a Choice column.
Fix: use ApprovalStatus/Value eq 'Pending' and map Action/Value, ApprovalStatus/Value in Select.

❌ "Configure the Get Items flow URL first"

Cause: endpoints not saved (browser storage blocked).
Fix: Import config → boxes turn green → Save endpoints → Test connection. App also reads live from the boxes.

❌ Multiple approvals for one sheet

Cause: Flow 1 has an Apply-to-each / Excel List-rows before the History step.
Fix: Flow 1 = Create file → ONE Create item (History) → Response. No loops.

❌ Get Users returns 0 / can't log in on another device (Flow 11)

Cause: the Response action's Body isn't set to the Select output (or Role comes back as a Choice object).
Fix: Flow 11 = Get items (GMT Users) → Select (login←Title, password←Password, role←Role) → Response, Body = body('Select'). Verify with 🧪 Test Get Users flow.

❌ New user not visible on other machines (Flow 10)

Cause: the account was saved locally but never written to the shared list.
Fix: set the Create User flow URL (Configuration ▸ #10) → Create item on GMT Users mapping Title = login, Password, Role. Re-create the user (or use 🔄 Sync users from database).

👥 Create login IDs, generate a random password and assign a role. New accounts are written to the shared SharePoint GMT Users list (via the Create User flow) and every device checks that list at login (via the Get Users flow) — so a user created here can sign in on their own machine. Configure both flows in the Configuration tab.
🩺 Ping all 11 flows and see live status. Green = reachable (the flow was contacted and ran). Red = a real problem (bad URL, missing signature, auth, or network/CORS). Uses the endpoints from the Configuration tab.
Note on Flow 4 (Delete), Flow 6 (Decide) & Flow 10 (Create User)

These two are shown as green / reachable even if this test gets an HTTP 502 back, because a 502 here means the flow was reached and did run — it just tried to look up this diagnostic's harmless placeholder id (0), which isn't a real record. They work normally when given a real, existing record id — i.e. during an actual Delete or Approve/Reject action in the app — this diagnostic simply can't safely test that without acting on real data.
